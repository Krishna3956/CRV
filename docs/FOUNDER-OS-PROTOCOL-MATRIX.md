# Founder OS protocol evidence matrix

This matrix is the product truth boundary for protocol coverage. “Observed”
means the current event envelope and dashboard can show the behavior. “Partial”
means only a bounded proxy is available. “Deferred” means the product must not
claim coverage until a fixture, persistence rule, and dashboard evidence path
exist. A missing observation is never interpreted as a successful or failed
protocol operation.

| Surface | Current evidence | Product status | Required evidence before claiming full coverage |
| --- | --- | --- | --- |
| `initialize` / negotiated protocol version | protocol event fields and versioned validation | Observed | Versioned fixtures for supported revisions |
| protocol revision boundary | Browser tester supports the legacy handshake revisions listed in its contract; a requested `2026-07-28` revision verifies the server advertises that revision, then runs bounded discovery/catalog calls and records `ttlMs`/`cacheScope` hints as observational evidence before stopping incomplete; Node client observer now records bounded request/response metadata for identified methods, cache hints, subscription acknowledgement, and invalidation signals | Partial | Complete conformance tests for server cache behavior, stream close/reconnect, MRTR, and the Tasks extension before claiming modern compatibility |
| `tools/list` | catalog metadata and bounded tool projections | Partial | Complete snapshot rows, pagination fixtures, historical joins; workspace-scoped timestamp cursor now exists for catalog history |
| `tools/call` | tool-call events, outcomes, latency, errors | Observed | Transport lifecycle and representative client fixtures |
| `resources/list` / `resources/read` | method-family counts, SDK-emitted SHA-256 resource-read identity counts, bounded Node client request/response observations, a bounded modern-client `resources/list` catalog page, and a review-ready idempotent entity-read projection | Partial | Apply and postflight the entity-read migration, then verify durable read-outcome joins; raw URI identities remain unavailable by design |
| `prompts/list` / `prompts/get` | method-family counts, SDK-emitted SHA-256 prompt-read identity counts, bounded Node client request/response observations, a bounded modern-client `prompts/list` catalog page, and a review-ready idempotent entity-read projection | Partial | Apply and postflight the entity-read migration, then verify durable input/completion joins; raw names/arguments remain unavailable by design |
| pagination | bounded request metadata where emitted; catalog history and v2 tools expose opaque cursors | Partial | Add protocol-level cursor fixtures and broader truncation evidence |
| cancellation | bounded retry/interaction fields | Partial | Client and server cancellation fixtures per transport |
| progress notifications | Canonical protocol events plus a bounded semantic `progress` signal; never counted as a business outcome | Implemented locally / bounded | Add SDK/exporter emission coverage and dashboard timeline |
| list-changed notifications / subscriptions | Canonical protocol events plus bounded `catalog_changed`, `resource_changed`, legacy subscribe/unsubscribe signals, modern `subscriptions/listen` request/acknowledgement `subscription_started` signals, and TypeScript client metadata emission coverage | Partial | Add stream close/reconnect, invalidation, and dashboard projections |
| completions | semantic fixtures plus TypeScript server-wrapper and Node client-observer response metadata; client observations now label `completion/*` calls as the bounded `completion` protocol family | Partial | Completion read model, broader runtime fixtures, and dashboard evidence |
| sampling | semantic fixtures plus TypeScript server-wrapper and Node client-observer response metadata; client observations now label `sampling/*` calls as the bounded `sampling` protocol family | Partial | Capability-aware durable request/result persistence, broader runtime fixtures, and privacy policy |
| elicitation | semantic fixtures plus TypeScript server-wrapper and Node client-observer response metadata; client observations now label `elicitation/*` calls as the bounded `elicitation` protocol family | Partial | User-input lifecycle persistence, broader runtime fixtures, and dashboard outcome evidence |
| MRTR input requests/responses | Bounded `input_request_count` and `input_response_count`, request-state SHA-256, interaction linkage, and retry linkage are accepted/projected; TypeScript and Python SDK response observation now emit bounded discriminator/count metadata; Node client observations label related modern calls by protocol family; raw request/response values are never stored | Partial | SDK/exporter coverage for all transports, explicit request/response lifecycle fixtures, and dashboard evidence before claiming complete MRTR conformance |
| tasks / workflows | bounded task IDs, explicit task-state classification, `/api/v2/tasks`, workflow correlation fields, `resultType: "task"` handle recognition, a service-role-only transition-history writer, an optional analytics join for durable transitions, and TypeScript server-wrapper lifecycle metadata with one-way hashed task handles for `tasks/*` responses exist; modern discovery records the advertised `io.modelcontextprotocol/tasks` extension without issuing the removed `tasks/list` operation | Partial | Server-directed task-creation fixtures plus broader `tasks/get`/`tasks/update`/`tasks/cancel` interoperability and cross-server journey joins |
| streamable HTTP | transport enum, browser tester boundary, bounded TypeScript failed-session evidence, in-flight request failure observations on transport errors/close, and explicit `session_reconnected` evidence when the caller restarts a wrapped transport | Partial | Transport-owned reconnect policy, stream termination, and proxy fixtures |
| stdio | transport enum and SDK documentation; TypeScript/Python initialize/shutdown boundaries, bounded TypeScript session duration, explicit Python transport metadata, drained in-flight request failures on Node transport errors, and explicit caller-driven reconnect evidence | Partial | Process-start/exit/crash fixtures, transport-owned reconnect policy, and local consumer evidence |
| OTLP/HTTP JSON | bounded authenticated receiver; production smoke accepted a current-time JSON span and export returned the mapped event | Implemented / bounded | Keep the smoke fixture in recurring release validation |
| OTLP/HTTP protobuf | bounded authenticated receiver with metadata-only protobuf decoding; local/CI interoperability and deployment smoke are green | Implemented / bounded | Run a separate authenticated pilot-key protobuf UAT; raw payloads and trace bodies remain unsupported |
| OTLP/gRPC | intentionally not implemented | Unsupported | Separate receiver and interoperability review |

The matrix is deliberately explicit about boundaries so a dashboard card can
display “unknown” or “insufficient evidence” without silently converting an
unobserved protocol surface into a product claim.
